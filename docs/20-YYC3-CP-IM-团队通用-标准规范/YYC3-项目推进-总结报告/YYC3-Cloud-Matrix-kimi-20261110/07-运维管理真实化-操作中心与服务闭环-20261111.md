# 07 · 运维管理真实化：操作中心 + 服务闭环

## 一、审计结论（改前）

| 模块 | 问题 |
|---|---|
| useOperationCenter | 3 个假模板种子（tpl1-3）、12 条假日志种子（log-1000~1011，含 Math.random 时间戳）、全部动作 setTimeout 假执行 |
| useServiceLoop | 六阶段 MOCK_STAGE_RESULTS 全部虚构（GPU-A100-03 延迟/迁移 45s/吞吐 148K 等）、假随机延迟、数据流图假带宽（2.4 GB/s 等）与假子标签（PostgreSQL + NAS） |

## 二、实现内容

### 2.1 服务闭环（useServiceLoop）六阶段全真实化

| 阶段 | 真实数据源/动作 |
|---|---|
| 监测 | useNodeSlice（WS 权威节点快照）统计异常信号（mem≥90 或 status≠active） |
| 分析 | deriveFromRealData（与 AI 决策同一派生引擎，口径一致，已导出复用） |
| 决策 | 筛选可自动执行建议（autoExecutable && !applied） |
| 执行 | **真实动作**：为每条可执行建议生成跟进工单（follow-up-slice，taskId `LOOP-<runId>-<recId>`） |
| 验证 | 真实等待 2.5s（一个 WS 推送周期）后重读指标做前后对比 |
| 优化 | 真实沉淀：读取 IndexedDB 在库告警规则数 + 本轮工单数，给出阈值调优建议 |

- 删除全部模拟延迟；同步阶段 duration 可为 0ms（verify 阶段含真实等待）
- 数据流图去假带宽：改为真实链路描述（WS 推送 · 2s/帧 / IndexedDB 本地 / PUT /rules 等）；节点子标签改为 yyc3-agent · 本机 / localStorage + IndexedDB

### 2.2 操作中心（useOperationCenter）

- **4 个真实动作**（不受 demoMode 影响，实测耗时与结果）：
  - 健康检查 qa10：fetch agent `/healthz`，报告 nodeId/RTT/WS 客户端数/规则数/运行时长
  - 导出日志 qa4：log-slice 全量导出 JSON 下载
  - 生成报告 qa5：节点 + 工单快照 JSON 下载
  - 备份配置 qa11：settings-ssot 导出（wsToken/aiApiKey 脱敏）+ API 端点
- 其余 8 个动作（重启节点/部署模型/模型迁移/队列/缓存/脚本等）：演示模式专属，关闭时门禁提示「需要接入对应服务端能力」且不产生任何日志/副作用
- 假模板/假日志种子清零；IndexedDB 历史假种子按已知 ID 一次性清除
- 操作日志 ID 修复：追加随机段防同毫秒碰撞
