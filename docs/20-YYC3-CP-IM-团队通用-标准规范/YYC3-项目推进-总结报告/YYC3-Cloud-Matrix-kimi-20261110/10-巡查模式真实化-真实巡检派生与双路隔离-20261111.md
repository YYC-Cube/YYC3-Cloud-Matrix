# 10 · 巡查模式真实化

## 一、审计结论（改造前）

| 位置 | 问题 | 级别 |
|------|------|------|
| `usePatrol.generateChecks` | 8 项检查全部 `Math.random` 编造（在线率/温度/证书有效期…） | P0 |
| `generateInitialHistory` | 5 条假巡查历史作为 IndexedDB 种子 | P1 |
| `buildResult.duration` | 随机 2~9s 假耗时 | P2 |
| demoMode 关闭时 | 巡查直接拒绝执行（toast 提示"需要接入真实数据源"）——真实数据源（node/follow-up/log slice + WS 状态）其实已具备 | P1 |
| 自动巡查定时器 | 依赖 demoMode，生产态永不调度 | P2 |

组件层（PatrolDashboard/Scheduler/History/Report）扫描干净，数据全部来自 usePatrol，无需改动。

## 二、落地方案（usePatrol v2）

- **真实巡检** `buildRealChecks()`：7 项检查从真实数据源派生——
  节点在线率 / GPU 均值 / GPU 峰值温度 / 内存均值（node-slice derived）、
  待处理告警工单（follow-up-slice）、近 24h 错误日志（log-slice）、
  agent 通道状态（WebSocketContext）；无节点时节点类检查标记 `skipped` 而非编造
- **演示隔离**：随机检查项改名 `generateDemoChecks()` 仅 demoMode 可达；
  演示结果 ID 带 `demo-` 前缀，关闭演示模式自动隐藏（持久化保留）
- **健康度修正**：只对非 skipped 项计分（skipped 不再拉低分数）
- **真实耗时**：duration 改为实测秒（一位小数）
- **自动调度**：定时器不再依赖 demoMode，真实巡查始终可调度
- **历史清洗**：挂载时按生成器签名一次性清除 IndexedDB 假数据——
  `patrol-init-*` 种子 + 旧随机检查项签名（`checks[0].id` 形如 `chk-001`）
- ID 防撞：`patrol-<ts>-<rand>`（沿用 follow-up-slice 同毫秒撞 ID 的修复经验）

## 四、设计说明

- 检查阈值（<85%、<75°C 等）属于**检查定义**而非数据，保留在代码中；后续如需可调，应进「告警规则」同款的持久化规则库（本阶段未做）
- 演示模式语义升级：demoMode 关闭 = 真实巡检（旧语义为拒绝执行），与告警规则/AI 决策的真实化方向一致
