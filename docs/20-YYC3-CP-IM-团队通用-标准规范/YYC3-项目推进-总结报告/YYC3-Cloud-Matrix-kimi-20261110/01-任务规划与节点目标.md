# 📋 YYC³ Cloud-Matrix 全局协同打通规划

## 规划总则

> **执行有规划，规划有节点，节点有目标，目标可评估**

**三条铁律**（贯穿全部阶段）：

1. **一切数据禁止硬编码** — 无真实来源的字段显示空态，绝不用虚构值占位
2. **无后端设计** — 数据只走两条路：本地持久化（localStorage/IndexedDB）+ 本地实时通道（yyc3-agent WS / Ollama 代理）；不引入任何云端依赖
3. **SSOT 单一事实源** — 每类数据只有一个权威 slice，组件不私藏数据副本

## 总体目标

将 8 大业务模块的数据来源从「DEFAULT 假种子 + Math.random 模拟」全面切换为
「**真实事件驱动 + 本地持久化 + 本地 Agent 实时采集**」，达成生产可用口径：
任何一个数字都能回答「它从哪来」。

## 架构目标态

```
┌─ 真实事件源 ─────────────────────────────────────────┐
│ yyc3-agent（:3113）· Ollama 代理（:3118）· 用户操作   │
└──────────┬──────────────────────────────────────────┘
           ▼ WS 消息 / 本地写入
┌─ Zustand Slices（18 域 · persist 持久化）────────────┐
│ 每域 SSOT：node / follow-up / log / metrics / ...     │
└──────────┬──────────────────────────────────────────┘
           ▼ useShallow 细粒度订阅
┌─ 8 大业务模块页面 ───────────────────────────────────┐
│ 无真实数据 → 空态（i18n），绝不显示虚构值             │
└──────────────────────────────────────────────────────┘
```

### Phase 2：业务记录域清理（P1，下次会话）

**Task 2.1：log-slice 真实化**
- 现状：`DEFAULT_LOGS` 假日志种子
- 目标：种子清空；真实日志来源 = WS alert 事件 + 用户操作审计（复用 `audit-log` 机制）+ agent 系统事件
- 验收：操作日志页只显示真实事件；空域显示 i18n 空态
- 风险：~15 个测试断言种子内容，需同步重写（参照本轮 follow-up-slice 模式）

**Task 2.2：app-slice recentOps 真实化**
- 现状：Dashboard「实时操作流」显示虚构部署记录
- 目标：种子清空；真实来源 = 用户在操作中心的实际操作 + WS 告警事件
- 验收：Dashboard 操作流在无操作时显示空态

**Task 2.3：Math.random hooks 处置**
- 范围：usePatrol / useOperationCenter / useAIDiagnostics / useSecurityMonitor / useServiceLoop / useReportExporter 等 12 个
- 策略二选一（逐 hook 定夺）：
  a) 有真实来源 → 改派生（如 useSecurityMonitor 部分指标可来自 navigator/performance API 真实值）
  b) 无真实来源 → 标注「演示模式」并挂到 settings 的演示开关下，生产默认关闭
- 验收：生产模式下全站无 Math.random 驱动的展示数据

**Task 2.4：useWebSocketData 初始假值清除**
- 现状：connecting 瞬间显示 3842/48ms/82.4%/138K/s
- 目标：初始值改 null，组件显示骨架/空态
- 风险：Dashboard 兜底 `??` 链已存在，改动面小

### Phase 3：通道治理与安全（P1）

**Task 3.1：DB Proxy 死链路物理删除**
- 前置：全仓 grep 确认 family-db-bridge / useDbData 无隐藏动态引用
- 删除：`lib/family-db-bridge.ts` + `hooks/useDbData.ts` + 关联测试
- 验收：tsc + 全量测试绿

**Task 3.2：WS 通道 token 鉴权**
- 设计：agent 启动生成/读取 `~/.yyc3/agent-token`；前端连接带 `?token=`；设置面板可配置
- 验收：无 token 连接被拒；错误配置有明确提示

**Task 3.3：db-queries 内存库语义澄清**
- 选项 A：DataEditorPanel 改接真实 slice（推荐）
- 选项 B：页面标题改为「演示数据编辑器」并挂演示开关

### Phase 4：多节点汇聚（P2，架构演进）

**Task 4.1：agent 分发包**
- agent/ 已是零依赖单文件，可直接 scp 到 iMac/NAS
- 补 install 脚本（launchd plist 模板已具备）

**Task 4.2：hub 汇聚层设计**
- 方案：主节点 agent 增加 upstream 模式，或前端直连多 agent（设置面板配多 endpoint，node-slice 按 id 区分来源）
- 推荐后者：前端多 WS 连接（无新增后端组件，符合无后端原则）
- 验收：两个真实节点同时上屏，activeNodes = "2/2"
