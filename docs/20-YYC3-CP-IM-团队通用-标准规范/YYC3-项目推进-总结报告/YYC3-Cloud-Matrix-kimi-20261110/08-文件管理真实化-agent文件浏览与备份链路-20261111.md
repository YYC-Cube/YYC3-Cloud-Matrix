# 08 · 文件管理真实化

## 一、审计结论（改造前）

| 模块 | 现状 | 问题 |
|------|------|------|
| `/files` 文件浏览 | `DEFAULT_FILE_TREE` 整树虚构（GPU-A100-01 假日志、`~/.yyc3-cloudpivot` 假路径） | P1 硬编码 |
| 文件内容编辑 | `getFileContent` 按扩展名生成假内容 | P1 硬编码 |

| `/host-files` | File System Access API | ✅ 本来就真实，未动 |

## 二、落地方案

### agent 端（`agent/yyc3-agent.mjs`）

- 白名单根 `FILE_ROOT = ~/.yyc3-cloud-matrix`，`resolveSafePath()` 拦截 `..` 逃逸与绝对路径（实测拦截 `../../etc/passwd`）
- `GET /files?token=&path=<rel>`：列目录（目录优先、隐藏点文件）/文件元信息
- `GET /files/content`：读文件（512KB 截断上限）
- `PUT /files/content {path,content}`：写文件（1MB 上限，自动 mkdir -p）
- 全部复用 `checkHttpAuth` 令牌鉴权（与 WS 同一 agent-token）

### 前端（`src/app/hooks/useLocalFileSystem.ts` v2 全文重写）

| 能力 | 真实数据源 |
|------|-----------|
| 目录浏览 | agent `GET /files` 实时拉取；根标签 `~/.yyc3-cloud-matrix`；无令牌/不可达 → 空列表 + `agentReachable=false`（UI 显示黄色提示条），绝不回退假数据 |
| 文件读/写 | `GET/PUT /files/content`（async）；保存成功自动刷新列表 |
| 日志 | 直连 log-slice SSOT（WS 告警/审计真实写入），删除 `generateMockLogs` |
| 报告 | 从 node-slice + follow-up-slice + log-slice + settings systemName 真实统计生成（json/md/csv 三格式） |
| 下载日志 | log-slice 真实日志导出 JSON 文件 |
| 执行备份 | `downloadFullBackup()` 全量备份（localStorage + IndexedDB + globalStore） |
| 清理缓存 | `idbClear("inference_cache")` + `sessionStorage.clear()`，toast 报真实条数 |
| 历史残留 | 挂载时一次性清除 fs-slice persist 的假文件树/假内容缓存 |

删除项：`DEFAULT_FILE_TREE`、`generateMockLogs`、`generateReportPreview` 假数据、
CRUD 系列（addFile/addDirectory/renameItem/deleteItem/deleteBatch/resetFileTree/
exportFileTree/importFileTree —— FileBrowser UI 本无这些入口，仅旧测试引用）。

### 组件适配（`LocalFileManager.tsx`）

- `FileDetailEditor` 的 `getContent/saveContent` 改 async/await，编辑按钮带「读取中…」态
- `canGoUp` 根判断改用导出常量 `AGENT_FS_ROOT_LABEL`
- 文件 Tab 顶部新增 agent 离线提示条（`data-testid="agent-offline-hint"`）
