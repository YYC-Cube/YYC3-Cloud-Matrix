# 06 · 告警规则双向闭环 + AI 决策真实化

- 「执行」告警规则双向闭环 + AI 决策真实化主线
- 唯一禁忌：可编辑项、增减项，拒绝硬编码
- 系统管理 = 全局唯一数据源总控；AI Family 不动；开发工具 IDE 忽略

## 二、断点诊断（改前现状）

| 链路 | 改前问题 |
|---|---|
| 告警规则 | `useAlertRules` 内置 6 条 GPU-A100 假规则 + 5 条假事件种子；`CreateRuleModal` 硬编码 12 个假节点、默认选中 `GPU-A100-01`；agent 阈值硬编码 mem>90/disk>85 —— **面板编辑不生效** |

## 三、实现内容

### 3.1 告警规则双向闭环（编辑即生效）

**下行（前端 → agent）**

- 新增 `src/app/lib/agent-rules-sync.ts`：
  - `deriveAgentHttpBase()`：ws(s)://host:port/path → http(s)://host:port
  - `toAgentWire()`：AlertRule → agent 线协议（提取 cooldownMinutes，剔除 escalation 等 agent 不用字段）
  - `syncAlertRulesToAgent()`：PUT `/rules?token=`（复用 WS 同一 agent-token），3s AbortController 超时，fire-and-forget
  - 未配置 wsToken 时静默跳过（no-token），不影响本地持久化
- `useAlertRules.ts`：规则变更后 800ms 防抖自动下发（覆盖创建/编辑/启停/删除全动作）

**agent 端（`agent/yyc3-agent.mjs`）**

- 删除 `memAlertThreshold`/`diskAlertThreshold` 硬编码
- 动态规则引擎 `evaluateAgentRules()`：支持 cpu/memory/disk 实测指标 × gt/gte/lt/lte/eq/neq 六种条件；边沿触发 + 冷却期防抖；targets 含 `*`/本机 nodeId/空 才评估
- 规则持久化 `~/.yyc3-cloud-matrix/alert-rules.json`（0600）；文件不存在时用内置兜底（mem>90 critical / disk>85 warning），一旦前端下发过（含空数组）即以前端为唯一事实源
- HTTP 端点：`GET /rules` / `PUT /rules`（token 鉴权，时序安全比较），CORS 回显 Origin + OPTIONS 预检，256KB 载荷上限，100 条规则上限
- `/healthz` 增加 `rules`/`rulesSource` 观测字段

**上行（agent → 前端）**：复用既有 alert → `ingestWSAlert` → 一键跟进的幂等链路，无需改动。

### 3.2 假种子清除（唯一禁忌落实）

- `useAlertRules`：MOCK_RULES/MOCK_EVENTS 删除，默认空列表；IndexedDB 中历史假种子按已知 ID（rule-001~006 / evt-001~005）加载后一次性清除
- `CreateRuleModal`：删除 12 个假节点常量与默认选中；新增 `availableNodes?: string[]` 属性，空态显示引导文案（新增 i18n `alerts.noAvailableNodes` 双语）
- `AlertRulesPanel`：availableNodes = 真实在线节点 ∪ 既有规则目标（编辑旧规则不丢已选节点）
- `ai-suggestion-slice`：假种子删除；persist `version: 2` + migrate 自动清空旧版持久化的假数据

### 3.3 AI 决策真实化

- `runAnalysis`：从 **useNodeSlice（WS 真实节点）+ useFollowUpSlice（真实告警工单）** 同步派生，无假延迟：
  - 节点 mem ≥90%/≥95% → memory_pressure（high/critical），建议排查进程/降载
  - 节点 temp ≥80°C（>0 才判定，0 为无数据）→ gpu_overheat
  - 节点 status=warning → error_burst（服务状态异常）
  - pending ALERT- 工单按来源聚合 → error_burst（N 条未处理告警）
- `applyRecommendation`：真实动作 = 生成可追踪跟进工单（写入 follow-up-slice，taskId `AI-<recId>`），不再 setTimeout 演戏
