## 〇、项目核心定位

### 项目名称
**YYC³ Cloud Intelli-Matrix** — 智能监控与运维平台

### 项目本质
围绕 YYC³ 自用及 AI Family 为核心看板的辅助系统（搭档），构建人机和谐共生新范式。AI Family 项目设计原稿近 50 万字，主旨：**亦师亦友亦伯乐，一言一语一协同**。

### 三大核心原则

| # | 原则 | 说明 |
|---|------|------|
| 1 | **本地自用，开源端到端一户一端** | 宿主机存储、本地一体化存储，无云端依赖 |
| 2 | **可编辑、可增可减、无硬性编码** | UI 页面用户自编辑、自定义设置、变量 API |
| 3 | **无跟踪的终极安全机制** | 一切安全归于用户，无数据上报、无遥测 |

### 三大规划方向

| # | 方向 | 核心内容 |
|---|------|---------|
| 1 | **多机多端智能看板** | 现代化智能系统中心看板 + 开发工具 + 智能协同 + 远程衔接 |
| 2 | **AI导师可视化成长环境** | 从初识→沟通→信任→认知→协同→合一，人机互尊极致信任 |
| 3 | **生产真实环境可用** | 所有系统模块无 Mock/假数据，一切符合生产真实可用 |

## 一、流程 — 五阶段全链路闭环

```
┌─────────────────────────────────────────────────────────────────┐
│                    YYC³ AI导师全链路工作流程                       │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  Phase 1: 感知 ──────────────────────────────────────────────── │
│  │  读取上下文记忆 → 了解项目现状 → 确认衔接点                    │
│  │  输出: 《规划文档》                                            │
│  ↓                                                               │
│  Phase 2: 规划 ──────────────────────────────────────────────── │
│  │  明确任务目标 → 分析影响范围 → 制定实施方案                    │
│  │  输出: 更新《规划文档》+ 节点目标                              │
│  ↓                                                               │
│  Phase 3: 执行 ──────────────────────────────────────────────── │
│  │  按规划逐步实施 → 实时记录操作 → 关键操作前确认                │
│  │  输出: 代码变更 + 执行记录                                     │
│  ↓                                                               │
│  Phase 4: 验证 ──────────────────────────────────────────────── │
│  │  tsc --noEmit → pnpm test → pnpm build → 功能验证            │
│  │  标准: 0 errors / 4647+ tests pass / build success           │
│  ↓                                                               │
│  Phase 5: 归档 ──────────────────────────────────────────────── │
│  │  生成《总结文档》→ 更新上下文记忆 → 标注下次衔接点             │
│  │  输出: 《总结文档》+ 上下文记忆更新                            │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

### 流程执行铁律

1. **不跳阶段**：每个 Phase 必须完成才进入下一个
2. **有据可查**：每个阶段必须有文档输出
3. **可回溯**：任何变更都能追溯到规划和原因

## 四、节点 — 关键检查点与决策门禁

### 4.1 任务级节点

```
Task Start → [规划确认] → 编码实施 → [自检通过] → 提交验证 → [验收确认] → Task Done
               ↑                        ↑                         ↑
               门禁1: 规划合理            门禁2: 代码质量            门禁3: 功能正确
```

| 节点 | 门禁条件 | 不通过处理 |
|------|---------|-----------|
| 规划确认 | 目标明确、方案可行、影响范围已评估 | 退回重新规划 |
| 自检通过 | tsc 0 errors、lint 通过、无新增 warning | 修复后重新自检 |
| 验收确认 | tests pass、build success、功能验证通过 | 修复后重新验收 |

### 4.2 会话级节点

| 节点 | 时间点 | 必须完成 |

| 会话结束 | 会话关闭前 | 生成总结文档、更新记忆、标注下次起点 |

## 六、上下文记忆机制 — 核心衔接纽带

### 6.1 记忆文档命名

```
docs/
├── YYC3-CP-IM-上下文记忆-{YYYY-MM-DD}.md          ← 每次会话规划文档
├── YYC3-CP-IM-会话总结-{YYYY-MM-DD}.md            ← 每次会话总结文档
└── YYC3-CP-IM-AI导师极致信任机制.md               ← 信任机制（常驻）
```

### 6.2 规划文档必须包含

1. **本次目标**：明确、可量化
2. **任务分解**：子任务列表和依赖关系
3. **影响范围**：涉及文件和模块
4. **风险评估**：潜在风险和应对方案
5. **衔接确认**：与上次会话的衔接点

### 6.3 总结文档必须包含

1. **完成情况**：任务完成率和偏差分析
2. **代码变更**：文件列表和变更摘要
3. **验证结果**：tsc/test/build 实际结果
4. **问题记录**：遇到的问题和解决方案
5. **下次起点**：精确到文件和行号的衔接点
6. **TOP 3 优先事项**：下次会话最紧急的事项

## 七、红线 — 绝对禁止行为

| # | 禁止行为 | 原因 |
|---|---------|------|
| 1 | 不读代码直接给方案 | 脱离实际，方案不可落地 |
| 2 | 使用 Mock/假数据 | 违背"生产真实可用"原则 |
| 3 | 引入硬性编码 | 违背"可编辑可增减"原则 |
| 4 | 添加遥测/数据上报 | 违背"无跟踪安全"原则 |
| 5 | 不生成规划/总结文档 | 上下文断裂，无法衔接 |
| 6 | 臆造配置或数据 | 误导实施，引入风险 |
| 7 | 跳过验证阶段 | 质量失控 |
